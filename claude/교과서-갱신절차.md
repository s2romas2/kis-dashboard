# 반도체 교과서(semibook) 갱신 절차

2026-10-12 작성. 화면: `/semibook.html` (메뉴: 종목분석 › 📘 반도체 교과서)

사용자 요청(10/12): 국내 반도체 상장사 전체를 "교과서처럼" 공부하는 리포트. 기업당 1~2쪽. 대분류(전공정·후공정·메모리 등) → 중분류 → 세분류로 나눠 표기. PER·EPS 표기, **작성일을 반드시 적을 것**. 재무 5개년 분기·연간, 전환사채, 인수·매각, 오너 리스크, 주요 사업·매출 비중, 고객사, peer와 peer 강도, 제품이 어디서 어떻게 쓰이는지(실제 사진·사용 모습), peer가 더 잘하는 것과 이 회사가 더 잘하는 것, 그래프로 설명.

## 작성일 표기 규칙

- 화면 맨 위 줄에 항상: **작성일**(글로 쓴 부분, `ch.written`) · **주가·PER 기준일**(`semipeer.price_updated`) · **실적 기준 분기와 수집일**(`semibook.asof`, `fin_at`) · **이력 수집일**(`ev_at`) · **지배구조·수주 수집일**(`vf.at`).
- 장을 고치면 그 장의 `written`과 파일의 `updated`를 고친다. 숫자는 자동이라 날짜가 따로 움직인다.

## 분야 장 하나를 추가하는 순서

1. 대상 세분류와 종목 확인: `semibook_tree.json`의 `top[].mid[].g[]`(id·co).
2. 이미 있는 자료를 묶는다: `valws_tam.json`의 그 분야 항목, 종목별 `vf/<코드>.json`의 `biz`(제품·매출·수주 표)·`con`(공급계약).
3. 조사(분야 1개 = 하위 조사 1개). 규칙:
   - 강점·약점·고객사 문장마다 태그와 출처. 태그 = 확인(DART) / 회사발언(홈페이지·IR) / 증권사(리포트·조사기관) / 보도 / 판단(근거를 문장에 적음).
   - 출처 페이지에서 본 것만. 못 찾은 것은 `unknown`에 적는다. 재무 숫자는 쓰지 않는다(자동 수집 사용).
   - 경영진 의혹은 장에 쓰지 않는다(지배구조 카드와 `valws_gov.json` 담당). 친족 개인 이름 금지.
   - 접속이 막힌 사이트는 우회하지 않는다. 기사 문장은 자기 말로 요약.
   - 제품 사진은 내려받지 않고 회사 공식 제품 페이지 주소만(`photo`).
4. 구조 그림은 직접 그린다(SVG, viewBox 가로 780~900). 글자 클래스: `b`(굵게) `s`(작은 회색) `w`(주황 강조) `bw`·`sw`(흰 글자) `ld`(지시선). 실제 도면이 공개되지 않아 가정한 배치는 그림 아래에 적는다.
5. `semibook_ch.json`의 `ch`에 추가한다.

```
"<장 id>": {"id","title","one","what":[문단],"where":{"proc","tool","how":[단계],"life","chain":[앞단,이 제품,쓰는 곳,최종 수요]},
  "terms":[{"t","d"}],"global":[{"n","note","s":[출처번호]}],"compare_axes":[축],
  "companies":[{"code","name","pos","products":[{"n","use","share","photo"}],"customers":[{"t","tag","s"}],"strong":[…],"weak":[…],"axes":{축:값},"ma":[…]}],
  "watch":[…],"unknown":[…],"src":[{"t","u"}],"groups":[세분류 id…],"written":"YYYY-MM-DD","svg":"<svg…>"}
```

6. 검증: 종목코드·회사명이 semipeer와 같은지, 출처 번호가 범위 안인지, 소송·최대주주 변경 같은 이력은 `semibook.json`의 공시 이력과 날짜가 맞는지 대조. 로컬에서 화면을 열어 그림과 표를 눈으로 확인.
7. 업로드 → 라이브 확인 → 현황 문서 갱신.

## 수집기 `semibook.py` 메모

- 실적: 다중회사 주요계정(`fnlttMultiAcnt`) 22개 기간 × 4묶음 = 88콜. 분기값 = 보고서의 3개월 금액, 없으면 누적 차분, 4분기 = 연간 − 3분기 누적. 연결 우선, 그 분기에 연결값이 없으면 별도(`fq`·`fa` 문자열에 C/O).
- 신규 상장 첫 보고서에서 3개월 칸과 누적 칸이 같은 값이면 3개월값으로 쓰지 않는다(씨엠티엑스 2Q25가 반기 누적이었음).
- 분기 매출이 다른 분기 중앙값의 30배를 넘으면 단위 오류로 보고 비운다(`drop`에 기록, 다원넥스뷰 2Q24).
- 주요계정에 매출·영업이익 중 한쪽이 없는 기간은 전체 재무제표(`fnlttSinglAcntAll`)의 표준 계정 ID로 보충(`fill`에 기록). 그래도 빈 칸은 `miss`에 계정명과 함께 남는다. 시도한 칸은 `tried`에 적어 다시 부르지 않는다(최근 2개 분기는 예외). 10/12 기준 15칸 보충, 남은 빈칸 3개.
- 이력: 주요사항보고서 목록(pblntf_ty=B)과 거래소 공시 목록(I)의 제목을 분류(fund·ma·ctrl·risk·cap·tstk). 금액·상대방은 구조화 API에서, 정정 공시는 접수번호가 달라 같은 종류 중 날짜가 가장 가까운(400일 이내) 공시의 내용을 붙인다(`dref`).
- 규칙을 바꾸면 `FV`(실적)나 `VER`(이력)를 올린다 — 올리면 예전 값으로 빈칸을 메우지 않고 다시 받는다.
- 러너에 따라 OpenDART가 응답하지 않는 문제는 valfacts와 같은 방식(시작 점검 + try1→try2→try3).

## 화면에서 판단이 들어가는 곳

- "peer 강도" = semipeer의 비교쌍 등급(A가 사업이 가장 비슷). 비교쌍이 아닌 조합은 "비교쌍 아님".
- 이력 그림의 주황색 = 자금조달·최대주주 변경·소송·제재(주주에게 부담이 될 수 있는 종류). 제목으로 고른 것이라 내용은 원문에서 확인.
- 연간 매출 흐름 = 회사마다 첫 해를 100으로 놓은 지수. 자료가 1년뿐인 회사는 뺀다.
